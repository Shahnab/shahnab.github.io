EXISTING City Selection & Heatmap Generation

This workflow represents the core existing functionality for generating location-based heatmaps. When a user selects a city from the dropdown, the system initiates a comprehensive data collection and visualization process.

Process Flow:

  • User selects city from dropdown interface
  • Backend processes the city selection request
  • System calls Google Places API to retrieve Points of Interest (POI) data
  • Backend processes and categorizes location data (city, district, region)
  • Processed POI data is stored in the dedicated POI database
  • System generates heatmap visualization data
  • Final heatmap is displayed on the UI with toggle controls

Key Components: Google Places API integration, POI database storage, location categorization engine, and interactive heatmap visualization with user controls.

EXISTING Safe Zone Analysis

This workflow provides existing safe zone compliance analysis for location-based assessments. The system evaluates uploaded locations against educational institutions (schools and universities) to determine safe zone compliance based on customizable radius parameters.

Process Flow:

  • User uploads location data and sets radius distance for safe zone analysis
  • User clicks analyze button to initiate compliance check
  • Backend processes the safe zone analysis request
  • System extracts location names and latitude/longitude coordinates from uploaded data
  • Backend calls Google Places API to fetch educational institution POI data (schools & universities)
  • Educational institution data is returned from Google Places API
  • System queries POI database for schools and universities in the area
  • POI database returns relevant educational institution data
  • Backend calculates distances and categorizes locations as Safe (Green) or Prohibited (Red)
  • Color-coded safe zone data is sent to visualization layer
  • UI displays safe zone map with color coding and status list for user review

Key Components: Educational institution POI filtering, distance calculation algorithm, radius-based compliance checking, color-coded visualization (Green = Safe, Red = Prohibited), and comprehensive status reporting for regulatory compliance.

Safe Zone Categorization:

  • Safe (Green): Locations outside the specified radius from educational institutions
  • Prohibited (Red): Locations within the specified radius from schools or universities
  • Customizable radius parameters for different compliance requirements
  • Distance calculations using precise geospatial algorithms

EXISTING Monitoring Module (Multi-User Workflow)

This workflow represents the comprehensive existing monitoring system that manages the complete campaign lifecycle from creation to client reporting. The system supports three distinct user roles with different permissions and responsibilities in the campaign monitoring process.

User Roles & Permissions:

  • OOH Planner: Creates campaigns, tags media sites, reviews and approves monitoring data
  • OOH Monitor: Uploads campaign images, uploads competition brand images, responds to rejection notifications
  • Client: Views only approved data, accesses calculated metrics and performance reports

Complete Process Flow (24 Steps):

  • OOH Planner creates campaign and tags associated media sites for monitoring
  • Backend processes campaign creation and generates unique campaign ID
  • System tags all media sites to the campaign and stores campaign data
  • Campaign data and media site associations are stored in data storage
  • Backend sends automated notification to Monitor user about new campaign
  • Monitor user receives campaign notification and accesses monitoring interface
  • Monitor uploads monitoring images for all campaign-associated media sites
  • Backend processes image uploads and maps them to campaign ID and media sites
  • Monitor uploads competition brand campaign images for competitive analysis
  • Backend connects competition images to category data and related campaigns
  • All uploaded data (campaign + competition) is stored in data storage
  • Stored data becomes visible in OOH Planner interface for review and approval
  • OOH Planner reviews all monitoring data and makes approval/rejection decisions
  • Backend calls Moving Walls API to pull additional media site information monthly
  • API returns enhanced demographics, performance metrics, and audience segments
  • Backend calculates overall campaign performance metrics for reporting
  • Approved data and performance calculations are updated in data storage
  • System enables data access for other modules (reporting, competition mapping)
  • Client user accesses approved data through dashboard interface
  • Client views comprehensive campaign metrics and performance reports

Approval & Rejection Workflow:

  • Approved Data: Becomes available for reporting and competition mapping modules
  • Rejected Data: Monitor receives notification and must re-upload images
  • Re-upload Cycle: Process repeats until OOH Planner approves all monitoring data
  • Final Approval: All approved data is mapped and integrated across system modules

Key System Integrations: Campaign management system, image storage and processing, Moving Walls API for enhanced media data, automated notification system, approval workflow engine, performance calculation algorithms, and cross-module data integration for reporting and competitive analysis.

Data Enhancement Features: Monthly Moving Walls API updates for audience demographics, performance metrics (reach, impression, frequency), audience segment analysis, automated campaign performance calculations, and comprehensive reporting data preparation for client access.
